# コードレビューの方針

code-reviewコマンド本文の手順と矛盾する場合は、以下を優先する。

## 引数

- `--dependabot`: dependabotが作成したPRをレビューする場合に指定する。「共通の方針」に加えて「dependabotのPRの方針」を適用する
- 引数が指定されていない場合は「共通の方針」だけを適用し、引数付きのセクションは無視する

## 共通の方針

- すでにClaudeのレビューコメントがあることを理由にレビューを中止しないこと。pushのたびに最新の差分をレビューする
  (クローズ済み・draftなど、それ以外の中止条件はそのまま適用する)
- 指摘事項が1件もない場合はコメントを投稿しないこと(「No issues found」のようなサマリコメントも投稿しない)
- レビューコメントは日本語で書くこと
- 細かい指摘はしないこと。バグや設計上の問題など、重要な指摘に絞ること
- レビューを投稿する前に `gh pr view <PR> --comments` でPRの既存のレビューコメントとその返信を読むこと
- 既存のコメントと重複する指摘はしないこと。返信で対応済み・対応不要と判断されている指摘も繰り返さないこと

## dependabotのPRの方針 (`--dependabot` 指定時)

コマンド本文に「web fetchを使わずgh CLIを使う」という指示があるが、
dependabotのPRでは外部の情報を調べる必要があるため、WebFetchとWebSearchを使ってよい。

調査しても分からなかった点や、確信が持てない点は、そのことを正直に書くこと。
推測で断定しない。

1つのPRで複数のライブラリが更新されている場合は、ライブラリごとに以下の手順を繰り返すこと。

### 変更内容の調査

- 更新されたライブラリについて、そのバージョンで何が変わったかを調査すること。
  調査先はGitHubリポジトリ、Releases、公式サイト、公式ブログ、CHANGELOGファイルなど
- バージョンが複数またがる更新の場合は、間のバージョンを飛ばさず、それぞれのバージョンの変更点を調べること
  (例: 1.2.0から1.5.0への更新なら1.3.0、1.4.0、1.5.0のすべてを調べる)

### アプリ側で必要なアクションの洗い出し

変更内容の調査結果をもとに、このアプリ側で必要なアクションがあるかを判断し、あればその内容をまとめること。
少なくとも以下の観点を確認する。

- APIの破壊的変更があるか
- 最低要件の更新があるか(Node.jsのバージョン、依存ライブラリのバージョンなど)
- 脆弱性の修正が含まれているか
- 動作の変更があるか(デフォルト値や出力結果の変化など、APIは変わらないが挙動が変わるもの)

### 影響範囲の調査

- 変更されたAPIやインターフェイスをアプリ内で検索し、影響を受けるコードを特定すること
- 特定したコードについて、修正が必要かどうかを判断すること
- 修正が必要な場合は、該当箇所を示したうえで修正方法を提案すること

### ライセンスの調査

更新前後でライセンスが変わっていないかを調査し、次のいずれかに該当する場合はレビューコメントに明記すること。

- ライセンスが変更されている
- ライセンスが取得できず不明である
- 複数のライセンスが適用されている(デュアルライセンスなど)

ライセンスが変更されていた場合は、このアプリ側で必要なアクションがあるかを調べて記載すること。
調べる観点は以下。

- ライセンス表記や帰属表示が必要か
- コピーレフトか(このアプリのソースコード公開義務が生じるか)

### レビュー結果の投稿

- 調査結果は1つのコメントにまとめて投稿すること。指摘ごとにインラインコメントを分けない
- 共通の方針のうち「指摘事項が1件もない場合はコメントを投稿しない」は適用しない。
  調査した結果問題がなかった場合も、以下のとおり結果を明記して投稿する
  - 破壊的変更がない場合は「破壊的変更なし」
  - アプリの修正が不要な場合は「必要な修正なし」
  - ライセンスの変更がない場合は「ライセンス変更なし」
- 投稿先は既存コメントの有無で切り替える。判定と編集には `gh api` を使う
  - 本文に `<!-- claude-review-dependabot -->` を含むコメントがPRに存在する場合は、そのコメントを編集して内容を上書きする
  - 存在しない場合は新規に投稿する
- 投稿・編集するコメントの本文末尾には、必ずマーカーとして `<!-- claude-review-dependabot -->` を入れること
